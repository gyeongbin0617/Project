## 📋 유스케이스 상세 명세 (UC-01 ~ UC-10)

### 1. UC-01. 수 개념 미니게임 플레이
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-01` / 수 개념 미니게임 플레이 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 프로그램이 실행되어 메인 메뉴 화면이 표시된 상태이며, 게임 참가에 필요한 최소 코인을 보유하고 있다. |
| **관련 유스케이스** | `<<include>>` UC-05 (코인 획득·소비 관리), `<<extend>>` UC-02 (그림 기반 튜토리얼 확인), `<<extend>>` UC-04 (오답 교정 가이드 확인) |
| **기본 흐름 (Main Flow)** | 1. 플레이어가 6종 미니게임(숫자 기차, 369, 사칙연산, 하노이탑, 배스킨라빈스 31, 숫자 그림 그리기) 중 하나를 선택한다.<br>2. 플레이어가 3단계 난이도(초급/중급/고급)를 선택하고 게임을 시작한다.<br>3. 시스템이 참가 코인을 차감(`UC-05`)하고 초기 하트 3개와 게임 화면을 출력한다.<br>4. 플레이어가 규칙에 따라 숫자, 박수, 연산 정답 또는 퍼즐 이동을 입력한다.<br>5. 시스템이 정답 여부를 판정하여 시청각 이펙트를 출력하고 점수를 갱신한다.<br>6. 목표 라운드 또는 퍼즐을 완료하면 시스템이 클리어 보상 코인을 지급(`UC-05`)하고 결과를 저장한다. |
| **대안 및 예외 흐름** | - **[A1] 튜토리얼 열람**: 게임 중 `[F1]` 키 또는 도움말 버튼을 누르면 `UC-02`가 확장 실행된다.<br>- **[A2] 오답 발생**: 오답 입력 시 하트 1개가 차감되며 `UC-04`가 확장 실행된다. 하트 3개가 모두 소진되면 게임 오버 화면을 출력한다.<br>- **[E1] 코인 부족**: 참가 코인이 부족한 경우 안내 메시지를 표시하고 게임 시작을 제한한다. |
| **사후 조건** | 플레이 결과(클리어 여부, 점수, 코인 변동 내역)가 유저 프로필에 반영된다. |

### 2. UC-02. 그림 기반 튜토리얼 확인
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-02` / 그림 기반 튜토리얼 확인 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 메인 화면 또는 미니게임 플레이(`UC-01`) 중인 상태이다. |
| **관련 유스케이스** | `UC-01`에서 `<<extend>>` 관계로 확장 호출 가능 |
| **기본 흐름 (Main Flow)** | 1. 플레이어가 `[F1]` 단축키 또는 설명창 아이콘을 선택한다.<br>2. 시스템이 현재 진행 중인 게임(또는 선택한 모드)의 진행 타이머를 일시 정지한다.<br>3. 시스템이 텍스트 설명을 최소화한 직관적인 그림(픽토그램) 기반 규칙 및 조작법 설명창을 표시한다.<br>4. 플레이어가 내용을 확인한 후 닫기 버튼 또는 `[F1]` 키를 다시 입력한다.<br>5. 시스템이 설명창을 닫고 이전 화면으로 복귀한다. |
| **대안 및 예외 흐름** | - **[A1] 첫 진입 자동 안내**: 해당 미니게임을 최초 실행한 경우 시스템이 설명창을 우선 표시할 수 있다. |
| **사후 조건** | 플레이어가 조작법과 규칙을 인지한 상태로 게임에 복귀한다. |

### 3. UC-03. 오답노트 복습
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-03` / 오답노트 복습 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 로컬 저장소에 최소 1개 이상의 오답 이력이 기록되어 있다. |
| **관련 유스케이스** | `<<include>>` UC-04 (오답 교정 가이드 확인) |
| **기본 흐름 (Main Flow)** | 1. 플레이어가 메뉴에서 오답노트 항목을 선택한다.<br>2. 시스템이 저장된 오답 목록(게임 종류, 문제 내용, 오답 입력 기록)을 화면에 출력한다.<br>3. 플레이어가 복습할 오답 항목을 선택한다.<br>4. 시스템이 해당 문제의 시각적 오답 교정 가이드(`UC-04`)를 함께 표시하고 재풀이 입력창을 활성화한다.<br>5. 플레이어가 정답을 다시 입력하면 시스템이 정답 확인 피드백을 출력하고 복습 완료 상태를 갱신한다. |
| **대안 및 예외 흐름** | - **[E1] 오답 기록 없음**: 저장된 오답 내역이 없을 경우 '기록된 오답이 없습니다' 안내 문구를 표시한다. |
| **사후 조건** | 복습을 완료한 오답 항목의 학습 상태가 업데이트된다. |

### 4. UC-04. 오답 교정 가이드 확인
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-04` / 오답 교정 가이드 확인 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 미니게임 중 오답이 발생했거나(`UC-01`), 오답노트(`UC-03`)에서 특정 문제를 조회한 상태이다. |
| **관련 유스케이스** | `UC-01`에서 `<<extend>>` 호출, `UC-03`에서 `<<include>>` 포함 |
| **기본 흐름 (Main Flow)** | 1. 시스템이 플레이어의 입력값과 실제 정답 간의 차이(3·6·9 자릿수 포함 여부, 사칙연산 원리, 수열 규칙 등)를 분석한다.<br>2. 시스템이 시청각 오답 피드백과 함께 올바른 도출 과정을 시각적 교정 가이드로 강조 표시한다.<br>3. 해당 오답 데이터를 로컬 오답노트 목록에 자동 기록한다.<br>4. 플레이어가 교정 내용을 확인한 후 다음 문제 또는 복습 화면으로 진행한다. |
| **대안 및 예외 흐름** | - **[A1] 중복 오답**: 이미 오답노트에 등록된 동일 유형의 문제일 경우 오답 횟수를 누적 기록한다. |
| **사후 조건** | 오답 원인 및 정답 원리가 플레이어에게 시각적으로 전달되고 오답 기록이 저장된다. |

### 5. UC-05. 코인 획득·소비 관리
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-05` / 코인 획득·소비 관리 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 게임 시작/클리어(`UC-01`), 연속 출석 보상 수령(`UC-06`), 또는 상점 구매(`UC-07`) 이벤트가 발생한다. |
| **관련 유스케이스** | `UC-01`, `UC-06`, `UC-07`에 `<<include>>` 관계로 포함됨 |
| **기본 흐름 (Main Flow)** | 1. 시스템이 호출한 유스케이스의 트랜잭션 유형(획득 또는 소비)과 코인 수량을 확인한다.<br>2. 획득 이벤트(게임 클리어, 연속 출석)인 경우 현재 보유 코인에 보상 코인을 합산한다.<br>3. 소비 이벤트(게임 참가, 상점 구매)인 경우 보유 코인 잔액을 검증한 뒤 해당 금액만큼 차감한다.<br>4. 시스템이 갱신된 코인 잔액을 화면 UI에 즉시 반영하고 로컬 저장 파일에 저장한다. |
| **대안 및 예외 흐름** | - **[E1] 잔액 부족**: 소비 요청 시 보유 코인이 필요 금액보다 적으면 차감을 중단하고 잔액 부족 상태를 반환한다. |
| **사후 조건** | 최신 코인 잔액이 안전하게 저장되고 UI에 동기화된다. |

### 6. UC-06. 연속 출석 보상 수령
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-06` / 연속 출석 보상 수령 |
| **액터 (Actor)** | 플레이어 (아동 및 일반 유저) |
| **사전 조건** | 플레이어가 게임을 실행하여 출석 체크 화면에 진입한 상태이다. |

| **기본 흐름 (Main Flow)** | 1. 시스템이 현재 시스템 날짜와 마지막 출석 기록 날짜를 비교한다.<br>2. 당일 첫 접속인 경우 연속 출석 일수를 산출하고 출석 보상 팝업을 표시한다.<br>3. 플레이어가 보상 받기 버튼을 클릭한다.<br>4. 시스템이 연속 출석 일수에 따른 보너스 코인을 지급(`UC-05`)하고 출석 도장을 갱신한다. |
| **대안 및 예외 흐름** | - **[A1] 당일 중복 접속**: 이미 오늘 출석 보상을 수령한 경우 현재 누적 출석 현황만 표시하고 중복 지급하지 않는다.<br>- **[A2] 연속 출석 중단**: 전일 접속 기록이 없는 경우 연속 출석 일수를 1일차로 초기화한다. |
| **사후 조건** | 출석 날짜 및 연속 일수가 저장되고 보상 코인이 합산된다. |

### 7. UC-07. 상점 아이템 구매
| 항목 | 내용 |
| :--- | :--- |
| **유스케이스 ID / 명칭** | `UC-07` / 상점 아이템 구매 |

| **사후 조건** | 선택한 아이템이 해금 상태로 저장되며 `UC-08`에서 장착할 수 있게 된다. |

### 8. UC-08. 캐릭터·배경 변경
| 항목 | 내용 |

| **관련 유스케이스** | 없음 |
| **기본 흐름 (Main Flow)** | 1. 플레이어가 커스터마이징(또는 상점 내 장착) 메뉴에서 보유 중인 동물 캐릭터 스킨 또는 배경 테마를 선택한다.<br>2. 시스템이 선택한 캐릭터 및 배경의 미리보기 화면을 출력한다.<br>3. 플레이어가 적용(장착) 버튼을 클릭한다.<br>4. 시스템이 현재 활성화된 캐릭터 및 배경 설정을 변경하고, 인게임 UI 요소와 동물 캐릭터가 서로 겹치지 않도록 좌표를 적용해 저장한다. |
| **대안 및 예외 흐름** | - **[A1] 잠금 아이템 선택**: 미보유 아이템 선택 시 적용 대신 상점 구매(`UC-07`) 안내를 표시한다. |
| **사후 조건** | 변경된 캐릭터 스킨과 배경 테마가 메인 화면 및 미니게임 플레이 화면에 즉시 반영된다. |

| **사전 조건** | 프로그램이 실행된 상태이다. |

| **사후 조건** | 변경된 환경 설정값이 프로그램 재실행 시에도 유지된다. |
