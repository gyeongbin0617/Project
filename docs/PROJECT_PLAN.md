# 📋 369 PARTY - 프로젝트 관리 계획서

## 1. 프로젝트 개요
- **프로젝트명**: 369 PARTY (3-6-9 파티)
- **장르**: 캐주얼 에듀테인먼트 + 실시간 파티 퀴즈 액션
- **타깃**: 수 개념을 배우는 아동·초등 저학년 및 파티 게임 유저층

### 🎯 프로젝트 비전 & 핵심 목표
- **프로젝트 비전**: 전통적인 '3·6·9 게임'의 룰을 직관적인 2지선다 버튼 조작(`[숫자]` / `[박수]`)과 타임어택 시스템으로 재해석하여, 아동에게는 수 개념 및 순발력 학습 효과를, 파티 유저에게는 관전 이탈 없는 유령 방해 대전의 재미를 제공하는 에듀테인먼트 플랫폼 구축
- **직관적 UI 기반 학습**: 직관적인 UI/UX 기반의 싱글 훈련 모드 구현 및 학습 보정 피드백 제공
- **동기부여 보상 루프**: 정답 및 연속 기록 기반 보상(코인) 시스템 및 캐릭터 수집 상점 구현
- **AI 봇 턴제 서바이벌**: 로컬 AI 봇 턴제 대전 엔진 및 아동용 수학 연산 학습 모드 구축

### 📦 주요 개발 범위 (Deliverables)
- **클라이언트 (v1.0 구현 완료)**: C/SDL2 기반 Custom 2D Engine, 싱글 훈련 모드 5종(기본 369, 아이템전, 탕수육, 더하기/빼기, 곱하기/나누기), 로컬 AI 봇 대전 서바이벌, 2지선다 입력 UI(`SPACE` / `C`), 상점(작은 옷장, 캐릭터 8종) 시스템, 타임어택 가속 엔진
- **서버/네트워크 (v2.0 확장 목표)**: 로컬 턴제 대전 AI 엔진 구축 완료 / Socket 기반 실시간 네트워크 턴 동기화 및 유령 스킬 패킷 처리는 v2.0 확장 목표로 정의

## 2. 개발 시스템 문맥 다이어그램
- **A. 외부 개체 (External Entities)**: 아동/초등 저학년, 일반 유저, 학부모/교육자
- **B. 개발 대상 시스템 (System Boundary)**: 369 PARTY 게임 시스템 (클라이언트 룰 판정, 타이머, UI 연출, 상점, AI 봇 및 동기화 모듈 포함)
- **C. 데이터 및 신호 흐름 (Interactions)**
  - **아동 유저 ↔ 시스템**: 조작 신호(`Space`/`C`, 마우스) 및 코인 소비 ➔ / ⬅ 게임 화면 UI, 시청각 피드백, 오답 교정 가이드, 수집 캐릭터 해금
  - **일반 유저 ↔ 시스템**: 조작 신호(`Space`/`C`, 마우스) ➔ / ⬅ 게임 화면 UI, 코인 및 캐릭터 해금 피드백
  - **학부모/교육자 ↔ 시스템**: ⬅ 아이의 학습 현황 및 플레이 확인
- **D. 범례 (Legend)**: 파란색 사각형 = 개발 대상 시스템 / 노란색 타원 = 외부 개체 (Actor) / 화살표 = 데이터 및 신호 흐름

## 5. 관리 계획

### 🛠️ 버전 및 형상 관리
- **관리 도구**: Git & GitHub
- **브랜치 전략 (Git-Flow)**:
  - `main`: 최종 검증 및 제출용 빌드 브랜치
  - `develop`: 기능 개발 통합 브랜치
  - `feature/기능명`: 세부 기능별 개발 브랜치 (예: `feature/single-game`, `feature/shop-ui`)
- **관리 규칙**: 코드 리뷰 후 PR(Pull Request)을 통한 병합, 이슈 트래커(Issue Tracker)를 활용한 작업 단위 추적

### 🎨 기술 및 리소스 관리
- **개발 환경**: C Language, SDL2 (SDL2_image, SDL2_ttf, SDL2_mixer) 기반 Custom 2D Engine
- **빌드 산출물**: Win32 C 응용 프로그램 (`369Party.exe`)
- **에셋 관리**: 원본 에셋(PNG/TTF/WAV)과 C 빌드 경로 내 `Assets/` 리소스 매핑 관리

### 🧪 품질 관리 (QA)
- **기능 테스트**: 각 스프린트 종료 시 핵심 로직(3·6·9 판정, 타임어택 타이머, 하트 차감) 및 로컬 AI 봇 턴 처리 점검
- **밸런싱 검증**: 아동 및 초등 저학년 타깃 유저 기준의 반응 속도를 고려한 난이도 가속 및 타임어택 수치 검증
