# 📋 369 PARTY - 프로젝트 관리 계획서

## 1. 프로젝트 개요
- **프로젝트명**: 369 PARTY
- **장르**: 캐주얼 에듀테인먼트 + 실시간 파티 퀴즈 액션
- **타깃**: 수 개념을 배우는 아동·초등 저학년 및 파티 게임 유저층

### 🎯 프로젝트 비전 & 핵심 목표
- **직관적 UI 기반 학습**: 싱글 훈련 모드 및 오답 교정 가이드 피드백 구현
- **동기부여 보상 루프**: 정답/연속 기록 보상 기반 코인 상점(동물 캐릭터 8종 해금) 구축
- **AI 봇 턴제 서바이벌**: 로컬 AI 봇 턴제 대전 엔진 및 기초 수학 연산 학습 모드 구축

---

## 2. 개발 시스템 문맥 다이어그램
- **사용자 (User)**: 키보드/마우스(`SPACE` / `C` / 클릭) 입력 → 시청각 피드백 및 보상 수신
- **외부 소셜/매칭 서버 (v2.0 확장 목표)**: 차기 버전 룸 매칭, 실시간 턴 동기화 및 방해 스킬 데이터 전송 (v1.0은 로컬 AI 봇 엔진으로 처리)
- **핵심 시스템**: C/SDL2 기반 369 룰 판정, 타임어택 타이머 제어, AI 봇 제어, 재화/상점 로직 수행

## 5. 관리 계획

### 🛠️ 형상 및 버전 관리
- **도구**: Git & GitHub
- **브랜치 전략**:
  - `main`: 최종 검증 및 제출용 안정화 브랜치
  - `develop`: 기능 통합 및 테스트 브랜치
  - `feature/기능명`: 세부 기능별 개발 브랜치 (`feature/single-game`, `feature/shop-ui`)
- **관리 규칙**: PR(Pull Request) 기반 병합 및 Issue Tracker 활용

### 🎨 기술 및 리소스 관리
- **개발 환경**: C Language / SDL2 (SDL2_image, SDL2_ttf, SDL2_mixer) 기반 Custom 2D Engine
- **빌드 산출물**: Win32 C 응용 프로그램 (`369Party.exe`)
- **에셋 관리**: 원본 에셋(PNG/TTF)과 C 빌드 경로 내 Assets/include 리소스 매핑 관리

### 🧪 품질 관리 (QA)
- **기능 테스트**: 스프린트별 핵심 로직(369 판정, 타임어택, 하트 차감) 및 AI 봇 턴 전환 딜레이 점검
- **밸런싱 검증**: 아동 타깃 반응속도 기준 난이도 가속 및 타임어택 수치 검증
